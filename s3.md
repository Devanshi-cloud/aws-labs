## What is Amazon S3?

**S3 = Simple Storage Service** — Object storage for the internet.

```
Upload file  →  Store in cloud  →  Access anytime
```

**Examples of stored files:** images, videos, backups, documents, logs

### Advantages

| Feature | Description |
|---|---|
| 🪣 Create Buckets | Containers for organizing data |
| 📦 Store Data | Unlimited objects, 0 KB → 5 TB each |
| 📥 Download Data | Retrieve anytime from anywhere |
| 🔐 Permissions | Control access via IAM & Bucket Policies |

---

## Core Concepts

### 1. Bucket

> **Bucket** = top-level container. Everything lives inside a bucket.

**Example:** `my-bucket/`

#### Bucket Naming Guidelines

| Rule | Details |
|---|---|
| ✅ Globally unique | No two buckets can share a name worldwide |
| ✅ 3–63 characters | — |
| ✅ Lowercase only | No uppercase letters |
| ✅ Numbers allowed | — |
| ❌ No underscores | Use hyphens instead |
| ❌ No uppercase | — |
| ❌ No IP-like names | e.g., `192.168.1.1` is invalid |

```
✅ Valid:   devanshi-backup-2026
❌ Invalid: Devanshi_Backup
```

#### Bucket Limits

| Limit Type | Value |
|---|---|
| Soft limit (default) | 100 buckets/account |
| Hard limit (on request) | 1000 buckets/account |

---

### 2. Region

Buckets are **region-specific**.

```
Examples:
  Mumbai   →  ap-south-1
  Oregon   →  us-west-2
```

**Why choose a region?**
- ⚡ Lower latency
- 💰 Lower cost
- ⚖️ Legal / compliance requirements

---

### 3. Object

> **Object** = actual file stored in S3 (not block storage).

```
Examples: photo.jpg  |  resume.pdf  |  video.mp4
```

#### Object Components

```
Object = Key + Value + Metadata + Version ID
```

| Component | Description |
|---|---|
| **Key** | File name/path — e.g., `photos/dog.jpg` |
| **Value** | Actual file content |
| **Metadata** | Extra info: size, content-type, created date |
| **Version ID** | Used when versioning is enabled |

#### Object Size

| Limit | Value |
|---|---|
| Minimum | 0 KB |
| Maximum | 5 TB |
| Single PUT max | 5 GB |

## Key Features

### Multipart Upload

Used for **large files** instead of uploading as one single file.

```
Split → Upload in parallel → Combine automatically
```

| Detail | Value |
|---|---|
| Recommended for | 5 MB → 5 TB |
| Single PUT limit | 5 GB |
| Benefits | Faster · Resumable · Reliable |

---

### Versioning in S3

Keep **multiple versions** of the same object.

```
report.pdf (v1)
report.pdf (v2)  ← overwritten
report.pdf (v3)  ← current
```

**Benefits:** recover deleted files · undo overwrites · backup history

> ⚠️ **Important:**
> - Disabled by default
> - Enabled at bucket level
> - Once enabled → cannot return to unversioned state

#### Delete Marker

When deleting a versioned object:
- ✅ Actual file stays
- ✅ Delete marker is added
- ✅ Older version can be restored

---

### Server Access Logging

Tracks all bucket activity.

**Logs include:** who accessed · when · what action · success/failure

**Useful for:** auditing · security monitoring

---

### Object Lock (WORM)

> **WORM = Write Once Read Many**

- ❌ Cannot modify
- ❌ Cannot delete

**Used for:** compliance · legal records · finance logs

> ⚠️ Only available on new buckets. Enables versioning automatically.

---

### Encryption in S3

| State | Protection |
|---|---|
| **In Transit** (moving over network) | HTTPS |
| **At Rest** (stored on disk) | Encryption types below |

#### Encryption Types

| Type | Who Manages Keys | Details |
|---|---|---|
| **SSE-S3** | AWS | Simple default option |
| **SSE-KMS** | AWS KMS | Audit trail + more control |
| **SSE-C** | Customer provides keys | AWS encrypts/decrypts |
| **Client-Side** | Customer | Encrypted before upload — best control |

### Static Website Hosting

Host HTML/CSS/JS websites directly on S3.

```
Examples: portfolio · resume site · landing page
```

**Steps:**
1. Enable static hosting on bucket
2. Set public read access
3. Upload `index.html`

**Website URL format:**
```
http://bucket-name.s3-website-region.amazonaws.com
```

---

### Lifecycle Management

Automates storage class movement and deletion.

```
Day   0  →  Standard
Day  30  →  Standard-IA
Day  90  →  Glacier
Day 365  →  Delete
```

**Benefits:** saves money · fully automatic

---

### Replication

Automatically copies objects between buckets.

| Type | Region | Use Case |
|---|---|---|
| **CRR** (Cross Region Replication) | Different regions | Disaster recovery · Global users |
| **SRR** (Same Region Replication) | Same region | Backups · Compliance |

```
CRR Example: Mumbai → Oregon
SRR Example: Mumbai Bucket A → Mumbai Bucket B
```

---

### CloudFront

> **CloudFront = CDN (Content Delivery Network)**

```
User requests file
       ↓
Nearest Edge Location responds
       ↓
Faster delivery ⚡
```

**Benefits:** low latency · caching · global speed

---

## Storage Classes

Choose based on **access frequency** and **cost**.

| Class | Use Case | Access Speed | Cost |
|---|---|---|---|
| **Standard** | Frequently accessed (app assets, websites) | Fastest | Higher |
| **Intelligent Tiering** | Unknown or changing access patterns | Auto | Auto-optimized |
| **Standard-IA** | Infrequent access (backups, old data) | Fast | Cheaper storage + retrieval fee |
| **One Zone-IA** | Same as IA but single AZ | Fast | Cheapest IA (less resilient) |
| **Glacier** | Long-term archive (min. 90 days) | Minutes–Hours | Low |
| **Glacier Deep Archive** | Rarely accessed (min. 180 days) | ~12 Hours | Cheapest |
